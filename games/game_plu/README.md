# Load Balancer

เอกสารอธิบายรายละเอียดและการทำงานของมินิเกม **Load Balancer** ในโฟลเดอร์ [`game_plu`](file:///D:/Project/Tpop-Project/games/game_plu)

## About the game
**Load Balancer** เป็นมินิเกมสไตล์จับจังหวะอาเขตจำลองสถานการณ์ของผู้ดูแลระบบหลังบ้านหรือผู้กระจายสัญญาณ พัฒนาโดย **สุวรรณชัย ชัยสุวรรณศรี (พลุ - 200)** หน้าที่ของผู้เล่นคือควบคุมตัวกระจายโหลด (Load Balancer) เพื่อจัดสรรทราฟฟิกหรือจัดคิวการรับส่ง API Request Packets ที่กำลังร่วงหล่นลงมาให้ตรงกับช่องทางและจังหวะเวลาประมวลผลของเครื่องเซิร์ฟเวอร์ หากผู้เล่นประมวลผลพลาดหรือจัดส่งช้าเกินไป จะส่งผลให้ระบบทำงานได้ไม่เต็มประสิทธิภาพ และท้ายที่สุดอาจเกิดภาวะเซิร์ฟเวอร์ล่ม (System Down) ได้

---

## Genre & Visual Style
- **Genre**: Rhythm / Action Arcade / Casual Simulation (แนวเกมแนวตั้งจับจังหวะ / เกมจำลองสถานการณ์สไตล์อาร์เคด)
- **Visual Style**: การออกแบบในสไตล์ **Retro 8-bit Pixel Art** ผสมผสานธีมคอมพิวเตอร์และนักพัฒนาโปรแกรม (Terminal/Developer Aesthetics) ตัวเกมใช้สีดึงดูดสายตาตามเฉดแม่สีแสงหลักตัดกับสีดำลึกของฉากหลัง โดยแต่ละเครื่องเซิร์ฟเวอร์จะมีสีสัญลักษณ์เฉพาะตัว ได้แก่ สีฟ้า (Cyan) สำหรับ `SRV-1`, สีชมพูบานเย็น (Magenta) สำหรับ `SRV-2`, และสีเขียวนีออน (Neon Green) สำหรับ `SRV-3` ตัวก้อนข้อมูลสื่อสารถูกดีไซน์เป็นแพลตฟอร์มบล็อกพิกเซลสลักสัญลักษณ์วงเล็บปีกกา `{}` เลียนแบบโครงสร้างข้อมูล JSON และมีตัวอักษรเป็นสไตล์พิกเซลผ่านฟอนต์ `Press Start 2P` จาก Google Fonts

## Gameplay Mechanics
- **Controls (การควบคุม)**:
  - กดปุ่มหมายเลข **1 / 2 / 3** บนคีย์บอร์ดเพื่อเลือกตอบสนองคำสั่งในเลนเซิร์ฟเวอร์หมายเลข 1 (ซ้าย), 2 (กลาง), และ 3 (ขวา) ตามลำดับ
  - สามารถคลิกเมาส์หรือแตะ (Tap) บนหน้าจอสัมผัสตรงพื้นที่แต่ละคอลัมน์เพื่อประมวลผลแทนคีย์บอร์ดได้
  - กดปุ่ม **Spacebar** เพื่อกู้ระบบคืนมา (Redeploy) เมื่อเซิร์ฟเวอร์ล่ม
- **Sync Line & Hit Tolerance (เส้นประมวลผลและระยะความแม่นยำ)**:
  - บริเวณส่วนล่างของจอภาพจะมีเส้นประสีฟ้าเรืองแสงเรียกว่า **Sync Line** ซึ่งเป็นพิกัดเป้าหมายในการกดประมวลผล Request
  - มีการกำหนดช่วงพิกัดกดได้ปลอดภัย (Hit Tolerance Zone) สูง-ต่ำ จากเส้นประประมาณ $40$ พิกเซล
- **Request Response & Health Status (การตอบสนองและสุขภาพเซิร์ฟเวอร์)**:
  - **200 OK**: กดเลือกเลนได้ตรงจังหวะขณะที่มี Packet อยู่ในพื้นที่ประมวลผล ได้คะแนนความสำเร็จ (Handled) +1 และเกิดข้อความสถานะสีเขียว
  - **400 Bad Request**: กดปุ่มส่งสัญญาณไปที่เลนที่ไม่มีก้อนข้อมูลกำลังตกผ่านเส้นประ (กดเปล่า / กดย้ำ) ทำให้สัญญาณรวน เสียสุขภาพระบบ Uptime ไปครั้งละ $4\%$ เกิดข้อความสถานะสีเหลือง
  - **503 Service Unavailable**: ปล่อยให้ API Packet หลุดตกหน้าจอโดยไม่ได้ประมวลผล (การขอข้อมูลหมดเวลา) เสียสุขภาพ Uptime ไปครั้งละ $12\%$ เกิดข้อความสถานะสีแดง
- **Uptime Health System (แถบสถานะการทำงาน)**:
  - มีค่าความเสถียรเริ่มต้นที่ $100\%$ แสดงผลในรูปแถบพลังงานสีเขียวด้านบนขวา ซึ่งจะค่อยๆ เปลี่ยนสถานะความสมบูรณ์เป็นสีเหลืองและแดงตามสุขภาพที่ทรุดโทรมลง
- **Speed & Interval Ramping (ระดับความท้าทายที่ทวีคูณ)**:
  - ยิ่งผู้เล่นตอบรับแพ็คเก็ตข้อมูลสำเร็จสูงเท่าใด ค่าความยากจะเพิ่มขึ้นทันทีโดยปรับความเร็วในการร่วงหล่นของ Request ($Speed = 2.2 + Score \times 0.04$) และร่นเวลาการสุ่มสปอว์นของแพ็คเก็ตคิวถัดไปให้สั้นและถี่ขึ้น
- **System Failure (สถานะล้มเหลว)**:
  - หากระบบไม่เสถียรจน Uptime ลดเหลือ $0\%$ เกมจะเปลี่ยนหน้าจอเป็นสัญลักษณ์สีแดงจำลองรหัสความผิดพลาด **500 INTERNAL SERVER ERROR** แสดงคะแนนสุดท้ายที่ผู้เล่นทำได้ และระบบรอให้ทำการ "Redeploy" อีกครั้ง

## Tech Stack
- **HTML5**: สำหรับจัดทำหน้าเว็บเดี่ยวครอบคลุม viewport ของอุปกรณ์เคลื่อนที่และคอมพิวเตอร์ตั้งโต๊ะ
- **CSS3**: ตกแต่งกรอบหน้าจอแบบไซไฟคลาสสิกด้วยการทำเงาสะท้อน (Drop-shadow glow), ตกแต่งฟอร์ม Overlay และกำหนดฟอนต์พิกเซล `Press Start 2P` ผ่าน Web Import API ของ Google Fonts
- **JavaScript (Vanilla JS - ES6)**: คอยควบคุมตรรกะเกมทั้งหมด ทั้งระบบสุ่มความน่าจะเป็นของเซิร์ฟเวอร์ที่รับ Request, อาร์เรย์การควบคุมตักศิลาประมวลผล (Flashes Array), และการลบข้อมูล (Filter cleanup) เมื่อก้อนข้อมูลไม่อยู่ในเฟรม
- **HTML5 Canvas 2D API (`CanvasRenderingContext2D`)**: เรนเดอร์ออบเจกต์ในเฟรมเรต 60 FPS วาดตัวกรอบเซิร์ฟเวอร์แบบมีเส้นขอบและตัวหนังสือกดรหัส, วาดแถบ Uptime ด้วยสัดส่วนร้อยละ (Percentage scaling), และฉายเอฟเฟกต์การกะพริบจางหาย (Alpha opacity fading effect) ของรหัสข้อผิดพลาดสถานะ
- **Game Engine Loop**: ขับเคลื่อนผ่าน `requestAnimationFrame` ควบคุมฟังก์ชัน `update()` และ `draw()` อย่างแม่นยำตามการรีเฟรชหน้าจอของเบราว์เซอร์
